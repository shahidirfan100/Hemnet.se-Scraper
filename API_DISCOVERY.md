## Selected API
- Endpoint: `https://www.hemnet.se/graphql`
- Method: `POST`
- Auth: None required for public listing search
- Pagination: `offset` parameter with `limit: 50` per request
- Primary Operation: `webSearchForSaleListings`
- Query Field: `searchForSaleListings(search, sort, limit, offset)`

## Why This API Was Selected
- Returns JSON directly
- Supports pagination via offset
- Returns many structured listing fields in a single request
- No session login required for public for-sale listings

## Notes
- Direct access to `/_next/data/...` endpoints was blocked with `403`.
- The GraphQL endpoint remained accessible and provided broader listing-card coverage.
- Hemnet is behind Cloudflare and can intermittently return an HTML challenge (`Just a moment...`) instead of JSON.
- The GraphQL `POST` works without a session bootstrap when the request uses a browser profile that Cloudflare accepts. An extra `GET` of the public search page is used only on retries to refresh clearance cookies.

## Request Client (impit)
- Client: `impit` (replaced `got-scraping`), one instance reused per browser profile + proxy session.
- Endpoint: `POST https://www.hemnet.se/graphql`, JSON body, header profile: `Accept`, `Accept-Language`, `Content-Type: application/json`, `Origin: https://www.hemnet.se`, `Referer: <start page>`.
- Fingerprint headers (User-Agent, `sec-ch-ua*`, `sec-fetch-*`) are generated by the emulated browser profile and are not set manually.
- Verified browser profiles against the live endpoint (bootstrap + GraphQL, repeated runs):

  | Profile | Result |
  |---|---|
  | `chrome151` | Works (200 JSON, consistent) |
  | `firefox144`, `firefox135` | Work (200 JSON) |
  | `okhttp5`, `okhttp4`, `okhttp3` | Work (200 JSON) |
  | `chrome142`, `chrome136` | GraphQL works |
  | `chrome` (default), `chrome131`, `chrome125`, `chrome124` | Blocked (403 Cloudflare) |
  | `firefox` (default) | GraphQL blocked (403) |
  | `ios18` | TLS connection error |

- Selected primary profile: `chrome151`. Retries rotate through `['chrome151', 'firefox144', 'okhttp5', 'chrome142']`.

## Failure Diagnostics
- On a request failure the actor reads this file first, then probes the start page and the GraphQL endpoint (status code, content type, short body snippet) before raising the error.
- Auto-healing: up to 6 bounded attempts with exponential backoff + jitter, rotating browser profile and proxy session, bootstrapping the session page on retries.
